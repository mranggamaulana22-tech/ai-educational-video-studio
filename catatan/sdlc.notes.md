# Phases in SDLC
Kursus: Intro to Software Engineering

## 1. Pengenalan Phases in SDLC
Software Development Life Cycle (SDLC) terdiri dari enam tahapan utama mulai dari perencanaan hingga pemeliharaan.

- Planning: mencatat requirement dan membuat Software Requirement Specification (SRS).
- Design: membuat dokumen arsitektur software dan desain sistem.
- Development: membagikan task dan menulis kode sesuai product requirement.
- Testing: mencoba aplikasi untuk memastikan aman, stabil, dan sesuai requirement.
- Deployment: menyiapkan production environment dan mendeploy aplikasi.
- Maintenance: memperbaiki bug dan code untuk kelancaran serta kestabilan aplikasi.
- **SDLC**: Software Development Life Cycle, siklus hidup pengembangan perangkat lunak.

## 2. Langkah 1: Identifikasi Stakeholders dan Menetapkan Tujuan
Tahap awal planning melibatkan identifikasi pemangku kepentingan serta penentuan tujuan dan objektif proyek.

- Identifikasi stakeholders meliputi decision maker/PM, end user, system administrator, engineering, marketing, sales, dan customer support.
- Goals adalah tujuan jangka panjang yang ingin dicapai.
- Objectives adalah hal yang dapat ditindaklanjuti dan diukur untuk mencapai target.
- **Stakeholders**: Pemangku kepentingan yang terlibat dalam proyek.
- **Goals**: Tujuan jangka panjang yang bisa dicapai.
- **Objectives**: Target yang dapat ditindaklanjuti dan diukur.

## 3. Penggalian dan Pendokumentasian Requirement
Kebutuhan digali melalui berbagai metode lalu didokumentasikan agar sejalan dengan goals dan mudah dipahami.

- Penggalian kebutuhan dilakukan melalui survei, kuesioner, dan interview.
- Dokumen requirement harus sejalan dengan goals, dapat dicapai, dan mudah dipahami oleh stakeholder.
- Analisis requirement harus konsisten, jelas, dan lengkap.
- Skala prioritas ditentukan berdasarkan apa yang harus ada, prioritas tinggi, dan bagus jika ada.
- **Requirement**: Kebutuhan atau spesifikasi yang harus dipenuhi oleh sistem.

## 4. Dokumen SRS (Software Requirements Specification)
SRS adalah dokumen output dari tahap planning yang merinci fungsionalitas, performa, batasan, dan kategori requirement.

- SRS mencakup fungsionalitas software, standar performa, tujuan, ruang lingkup, serta batasan dan asumsi.
- Functional requirement adalah fitur yang harus bisa dilakukan oleh sistem.
- External interface requirement menjelaskan interaksi sistem dengan komponen eksternal.
- System feature menjelaskan fitur utama dan detail perilakunya.
- Non-functional requirement menjelaskan kualitas sistem seperti security, performa, usability, dan reliability.
- **SRS**: Software Requirements Specification, dokumen spesifikasi kebutuhan perangkat lunak.
- **Functional Requirement**: Fitur yang harus bisa dilakukan oleh sistem.
- **Non-functional Requirement**: Kualitas sistem yang harus dipenuhi seperti security dan performa.

## 5. Dokumen URS (User Requirement Specification)
URS mendeskripsikan kebutuhan bisnis dan ekspektasi user yang dikonfirmasi melalui UAT.

- Mendeskripsikan apa yang bisnis butuhkan dan ekspektasi user.
- Menggunakan user stories untuk menjawab siapa pengguna, fitur yang dibutuhkan, dan alasan pengguna membutuhkannya.
- Dikonfirmasi melalui User Acceptance Testing (UAT).
- URS nantinya digabungkan ke dalam SRS.
- **URS**: User Requirement Specification, dokumen kebutuhan pengguna.
- **UAT**: User Acceptance Testing, proses pengujian oleh pengguna untuk memastikan aplikasi sesuai kebutuhan.

## 6. Dokumen SysRS (System Requirement Specification)
SysRS merinci kemampuan sistem, karakteristik antarmuka, kebijakan, regulasi, performa, security, dan ekspektasi hardware.

- Menjelaskan kemampuan sistem (system capabilities) dan karakteristik pengguna/interface.
- Memuat policy (kebijakan internal) dan regulation (standar eksternal).
- Menjelaskan personel, performance, security, system acceptance criteria, dan hardware expectation.
- **SysRS**: System Requirement Specification, dokumen spesifikasi kebutuhan sistem.
